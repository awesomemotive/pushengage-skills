# PushEngage Dashboard Setup (Flutter)

A Flutter app that ships to both stores needs **TWO PushEngage sites** — one Android, one iOS — because each platform site generates its own App ID UUID. Skipping the second site (or reusing one UUID across both platforms) is the most common cross-platform Flutter integration mistake (KI-F006).

> If the customer is shipping to one platform only, create just one site (skip the other).

## Pre-requisites

- For the Android site: customer has finished `firebase-setup.md` and has the Service Account JSON file path + Sender ID + `applicationId` captured.
- For the iOS site: customer has finished `apns-setup.md` and has the `.p12` file path + password + iOS Bundle Identifier captured.

## Android site configuration

Navigate: **PushEngage dashboard → Site Settings → Installation → Android SDK**.

| Field | Value |
|---|---|
| **Firebase Sender ID** | The numeric Sender ID captured in `firebase-setup.md` Step 5. |
| **Service Account JSON** | Upload field. Customer uploads the `.json` file from their local machine. **Do NOT ask them to paste contents in chat.** |
| (Click) **Update** | Saves the credentials. |

After clicking Update, the dashboard shows the **App ID UUID** (under "Install the SDK" section). Ask the customer to copy and paste the UUID into chat.

The Android App ID UUID is **not a secret** — it's a public identifier the SDK transmits in every API call. Capture it for use in `init-code.md`'s `setAppId(...)` call.

## iOS site configuration

Navigate: **PushEngage dashboard → Site Settings → Installation → iOS SDK**.

| Field | Value |
|---|---|
| **App Push Id** | The iOS Bundle Identifier captured in `apns-setup.md`. (Confusingly named on the dashboard — it's the bundle ID, not a UUID.) |
| **Certificate (.p12)** | Upload field. Customer uploads the `.p12` file. |
| **Private Key Password** | The password set during `.p12` export. |
| (Click) **Update** | Saves the credentials. |

After clicking Update, the "Install the SDK" section shows the **iOS App ID UUID**. Ask the customer to copy and paste it into chat.

The iOS App ID UUID is **different** from the Android App ID UUID. Both are needed for cross-platform Flutter apps.

## Storage in chat — confirm both UUIDs

Before moving on, restate both UUIDs back to the customer for confirmation:

> "Android App ID: `<paste from above>`
> iOS App ID: `<paste from above>`
>
> I'll plug these into `lib/main.dart` as `Platform.isIOS ? '<iOS UUID>' : '<Android UUID>'`. Confirm both look right before I proceed?"

If the customer is shipping to one platform only, just capture that one UUID. Don't fake a UUID for the other platform — the code will branch on `Platform.is*` and the unused side stays empty.

## Field disambiguation cheat-sheet

The PushEngage dashboard uses **two fields that both sound like "App ID":**

| Dashboard field | What it actually is | Where it goes |
|---|---|---|
| **App Push Id** (iOS site) | iOS Bundle Identifier | Set in Xcode Runner target. NOT used in code. |
| **App ID** (under "Install the SDK") | UUID generated by PushEngage | Used in `setAppId(...)` in `lib/main.dart`. |

Never conflate them. The skill should always be explicit which one it's asking for.
