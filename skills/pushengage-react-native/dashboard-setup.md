# PushEngage Dashboard Setup (React Native)

An RN app shipping to both stores needs **TWO PushEngage sites** — one Android, one iOS — because each platform site generates its own App ID UUID. Skipping the second site (or reusing one UUID) is the most common cross-platform RN integration mistake (KI-RN006).

> If the customer is shipping to one platform only, create just one site.

## Pre-requisites

- For the Android site: customer has finished `firebase-setup.md` and has the Service Account JSON file path + Sender ID + `applicationId` captured.
- For the iOS site: customer has finished `apns-setup.md` and has the `.p12` file path + password + iOS Bundle Identifier captured.

## Android site configuration

Navigate: **PushEngage dashboard → Site Settings → Installation → Android SDK**.

| Field | Value |
|---|---|
| **Firebase Sender ID** | Numeric Sender ID captured in `firebase-setup.md`. |
| **Service Account JSON** | Upload field. Customer uploads the `.json` file. **Do NOT ask them to paste contents in chat.** |
| (Click) **Update** | Saves. |

After Update, the "Install the SDK" section reveals the **App ID UUID**. Ask the customer to copy and paste it into chat. Public identifier, not a secret.

## iOS site configuration

Navigate: **PushEngage dashboard → Site Settings → Installation → iOS SDK**.

| Field | Value |
|---|---|
| **App Push Id** | iOS Bundle Identifier from `apns-setup.md`. (Field is confusingly named — it's the Bundle ID, not a UUID.) |
| **Certificate (.p12)** | Upload field. Customer uploads `.p12`. |
| **Private Key Password** | The password set during `.p12` export. |
| (Click) **Update** | Saves. |

After Update, copy the **iOS App ID UUID**. DIFFERENT from the Android App ID UUID. Capture it.

## Confirm both UUIDs

Restate to the customer:

> "Android App ID: `<paste>`
> iOS App ID: `<paste>`
>
> I'll plug these into `index.js` as `Platform.OS === 'ios' ? '<iOS UUID>' : '<Android UUID>'`. Confirm before I proceed?"

If shipping to one platform only, just capture that one UUID.

## Field disambiguation cheat-sheet

| Dashboard field | What it actually is | Where it goes |
|---|---|---|
| **App Push Id** (iOS site) | iOS Bundle Identifier | Already set in the Xcode main app target's Signing & Capabilities. NOT used in JS code. |
| **App ID** (under "Install the SDK") | UUID generated by PushEngage | Used in `setAppId(...)` in `index.js`. |

Never conflate them. Always ask explicitly which one you want.
